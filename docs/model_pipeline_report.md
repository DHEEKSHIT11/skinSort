This is the final write-up. The working log with every intermediate result is
[model_pipeline_plan.md](model_pipeline_plan.md). Numbers come from `outputs/` (regenerated by the scripts) and

## 1. Summary

SkinSort ranks teledermatology cases by urgency (routine / priority / **urgent**). The model pipeline trains an
image backbone on dermoscopy photos and adds the patient's 6 questionnaire answers for phone photos. It calibrates
`P(urgent)`, picks a threshold tau for a recall target, checks and mitigates bias by slice, and selects the model
after the bias check. It then registers the model with a validation gate and serves it from a Docker image.

**Production model:** `skinsort-triage` v3 = `fusion_oof_rw`.
- Inputs: efficientnet_b3 image features plus the answers.
- Fusion head trained with Kamiran & Calders reweighing by sex × body site.
- Calibration and tau 0.076 fitted out-of-fold on 1,946 phone photos (209 urgent).
- Produced by one clean run of `python -m src.training.pipeline` (all six steps).

| Test set | Model | Urgent recall @ tau (target) | Precision | Flagged | Urgent AUC | Calibration error (≤ 0.05) |
|---|---|---|---|---|---|---|
| `test`: 2,868 dermoscopy photos, 630 urgent | efficientnet_b3 image model | 0.873 (0.90) ❌ | 0.597 | 32% | 0.934 | 0.031 ✅ |
| `pad_test`: 339 phone photos, 35 urgent | fusion_oof_rw | 0.743 (0.85) ❌ | 0.158 | 49% | 0.694 | 0.021 ✅ |

Neither recall target is met. For phone photos the more reliable estimate is out-of-fold (209 urgent): recall
0.852 at 52% flagged. On photos where every answer was given it is 0.796 (section 7.3), and the out-of-fold
estimate is itself slightly optimistic (section 4).

## 3. Models and selection (PDF §2.2, §4, §8.3, §8.6)

### Stage 1: image backbones

- Trained with `src/training/train.py` on an L4 GPU on the GCP VM: 384 px, class weights [1, 1.5, 3], early
  stopping on validation urgent AUC. Each run logs its parameters, per-epoch metrics and `best.pt` to MLflow.
- Ranked with `mlflow.search_runs(order_by=['metrics.best_urgent_auc DESC'])`, as in the course MLflow lab
  (`src/training/select_model.py`).
- Chart: [backbone comparison](figures/selection/selection_backbone_comparison.png).

| Backbone | Val urgent AUC | Val urgent recall | Val macro F1 | Params | CPU ms / photo (varies by run) |
|---|---|---|---|---|---|
| **efficientnet_b3** ✅ | **0.932** | 0.812 | 0.776 | 10.7 M | ~200 |
| resnet50 | 0.929 | 0.895 | 0.754 | 23.5 M | ~35–40 |
| convnext_tiny | 0.877 | 0.851 | 0.626 | 27.8 M | ~370–500 |

efficientnet_b3 and resnet50 are effectively tied on AUC. b3 is half the size, but resnet50 is about 5× faster on
CPU.

### Stage 2: phone triage model

Phone photos look different from dermoscopy: image-only AUC drops to 0.66. A small fusion head
(`src/models/fusion_model.py`) therefore combines the frozen image features with the 6 answers and 6
"answer missing" flags.

| Version | What changed | Outcome |
|---|---|---|
| Fusion on frozen b3 | answers added | pad_val AUC 0.656 → 0.778 |
| b3 fine-tuned on pad_train (batch 8) | phone photos in the backbone | AUC 0.808; exploding features on 1–2% of photos broke calibration |
| Fine-tune with frozen BatchNorm (`fusion_pad`) | fix for the above | AUC 0.805; the backbone had seen pad_train (leak, below), and tau came from 31 urgent photos |
| Hyperopt-tuned head (`fusion_pad_tuned`) | tuned settings | pad_val 0.869, but tau did not transfer (pad_test recall 0.543) |
| `fusion_oof` (`src/training/fit_final.py`) | original b3 backbone (never saw phone photos); tau and calibration fitted out-of-fold on pad_train + pad_val | best validation AUC; 3 bias slices fail |
| `fusion_oof_tuned` | settings from Hyperopt on the final backbone | tied out-of-fold |
| **`fusion_oof_rw`** | `fusion_oof` + Kamiran & Calders reweighing by sex × body site (`--reweight`) | **selected**: 1 bias slice fails |

**Leak found and fixed.** The fine-tuned backbone has image-only AUC 0.839 on pad_train but 0.743 on pad_val, so
any score computed on pad_train was too optimistic. `train.py` now records `trained_on` in each checkpoint, and
`fit_final.py` refuses a backbone whose `trained_on` splits overlap the photos used for the threshold.

### Selection rule

`select_model.py` uses validation data only. Test numbers are logged for the report and never enter the choice.

1. **Filters:** validation calibration error ≤ 0.05; tau fitted on ≥ 100 urgent photos; the model is servable.
2. **Rank:** `search_runs(order_by=['metrics.val_urgent_auc DESC'])`, on the pad_val photos.
3. **Bias:** among eligible candidates within 0.02 AUC of the best, the one with the fewest failing bias slices
   wins.

**Disclosure.** Step 3 originally preferred only a candidate that passes the bias check outright. It was changed to
"fewest failing slices" after the reweighting experiment. With the old rule, every candidate counted as equally
failing, even though one fails 1 slice and another fails 3.

| Candidate | Val AUC (pad_val photos) | Tau from | Bias (failing slices) | Result |
|---|---|---|---|---|
| fusion_pad_tuned | 0.869 | 31 urgent | inconclusive | filtered (too few urgent for tau) |
| fusion_oof | 0.813 | 209 urgent | FAIL (3) | eligible |
| **fusion_oof_rw** | **0.807** | 209 urgent | FAIL (1: sex) | **selected**: fewest failing slices within 0.02 AUC |
| fusion_pad | 0.806 | 31 urgent | inconclusive | filtered |
| fusion_oof_tuned | 0.800 | 209 urgent | FAIL | eligible |
| baseline: answers only (logistic regression) | 0.781 | 209 | FAIL | baseline |
| baseline: image only (dermoscopy model) | 0.663 | 209 | FAIL | baseline |
| baseline: prevalence (same score for all) | 0.500 | 209 | PASS (flags everyone) | baseline |

The image adds only about 0.03 AUC over the answers alone.
- Charts: [phone comparison](figures/selection/selection_phone_comparison.png).
- Details: [model_selection.md](figures/selection/selection_model_selection.md).
- In CI the runner has only the backbone it downloads and the model it builds, so there the comparison is that
  model against the baselines.

## 4. Validation (PDF §2.3, §8.4)

`evaluate.py` (image models) and `fit_final.py` (phone model) follow the same protocol:
1. Fit calibration on validation: a temperature plus a per-class offset.
2. Set tau to the highest threshold that still reaches the recall target on validation.
3. Score the test split once with both.

Outputs per model are in `outputs/evaluation/<name>/` (metrics.json, predictions.csv, confusion matrix,
calibration plot). Copies are in [figures/validation](figures/README.md).

For the phone model, "validation" means out-of-fold:
- pad_train + pad_val are split into 5 folds, grouped by patient.
- Each photo is scored by a head that never saw it.

This estimate is slightly optimistic, for two reasons:
- The epoch count is the median best epoch on the same folds.
- Tau comes from heads trained on 80% of the photos, then applied to the head trained on all of them.

**Disclosure.** `test` and `pad_test` were scored several times while fixing evaluation bugs. `pad_test` was also
used to compare phone versions during development (section 3). Tau, calibration, the selection rule and the
registry gate use validation / out-of-fold data only.

**pad_test is unrepresentative.** 34 of its 35 urgent photos are SCC and only 1 is melanoma; pad_train and pad_val
are about 25% melanoma. SCC is the hardest case because it resembles BCC and actinic keratosis. The phone model
catches about 25 of the 34 SCC photos (95% interval 0.57–0.85), against 0.85 out-of-fold. The data pipeline should
re-split the phone photos stratified by diagnosis.

## 5. Bias (PDF §2.4, §2.5, §6, §8.5)

`src/training/bias.py` runs Fairlearn `MetricFrame` per slice. The slices come from `params.yaml` `bias:`: sex,
age group, body site, skin tone, source.
- Metrics per group: urgent recall (with 95% interval), precision, urgent F1, accuracy and flagged share.
- A slice fails if the urgent-recall gap between groups is above 0.05.
- Groups with fewer than 20 urgent photos are shown but not used for the gap.

Reports and charts: `outputs/bias/<model>/`, copies in [figures/bias](figures/README.md).

**Image model** (test + fairness_test):
- Sex passes (gap 0.015).
- It fails on age (0–30: 0.714), body site (acral 0.667) and source (HAM10000 0.776 vs ISIC 0.904).
- It also fails on skin tone in fairness_test (gap 0.17). But every skin tone is out of domain there (recall ~0.55
  for all).

Per-group thresholds for the image model:

| Slice | Gap before → after | Cost |
|---|---|---|
| source | 0.127 → 0.002 | +4.5 points flagged |
| skin tone (fairness_test) | 0.174 → 0.043 | flagged 48% → 85%, so not usable |
| age, body site | unchanged | too few urgent validation cases in the weak groups |

**Phone model**: out-of-fold rows (1,946 photos). pad_test groups are too small (35 urgent).

| Slice | fusion_oof (no mitigation) | + per-group thresholds | **fusion_oof_rw** (reweighing) | + per-group thresholds |
|---|---|---|---|---|
| sex | 0.108 ❌ (female 0.794) | 0.046 ✅ | 0.069 ❌ (female 0.814) | **0.039 ✅** (female tau 0.062) |
| body site | 0.130 ❌ (acral 0.750) | 0.130 ❌ | **0.050 ✅** (acral 0.833) | 0.036 ✅ |
| skin tone | 0.052 ❌ | 0.045 ✅ | **0.022 ✅** | 0.014 ✅ |
| age group | 0.043 ✅ | — | 0.043 ✅ | — |
| flagged share | 51.2% | 54.7% | 51.6% | 52–55% |
| out-of-fold AUC | 0.774 | — | 0.769 | — |

How each mitigation works:
- **Reweighing** uses the same Kamiran & Calders formula the data pipeline exports for the model team
  (`Data-Pipeline/scripts/validation/bias.py`): weight = P(group) · P(label) / P(group, label). The weights are
  computed inside each fold on its training rows only.
- **Per-group thresholds** are cross-fitted by patient halves. Thresholds fitted on one half are applied to the
  other half, and they only go down.

Trade-offs:
- Reweighing costs about 0.005 out-of-fold AUC and closes the acral and skin-tone gaps.
- The remaining sex gap closes only with a lower threshold for women. That raises the share of women's photos
  flagged from 63% to 74%, which means more doctor review and no extra misses.
- A per-group threshold needs the group at prediction time. The intake today sends photo + answers only. So the
  registered model uses the single tau, and the sex threshold is ready once the intake form asks for sex.
- The image model's age and body-site gaps would need more young-patient and acral urgent cases.

**Dataset artifacts.**
- Photos without demographics (794, sex "unknown") contain no urgent cases.
- Photos with the "changed" or "grew" answer missing are 2.5× more likely to be urgent (21% vs 8.5%).
- See section 7.3 for what this means for the model.

## 6. Hyperparameter tuning (PDF §3)

`src/training/tune.py` uses Hyperopt TPE (Bayesian optimisation), as in the course MLflow lab: one parent run and
one nested run per trial.
- Each trial is a 5-fold cross-validation on pad_train, grouped by patient (963 patients). pad_val and pad_test
  are not used.
- Search space (`params.yaml` `tuning:`), 20 trials:
  - lr 1e-5–1e-3 (log scale)
  - weight_decay 1e-5–1e-2 (log scale)
  - dropout 0–0.5
  - urgent class weight 2–6
  - hidden_dim {32, 64, 128}

| Search | Image features | Best trial (CV urgent AUC) | params.yaml settings (CV) | Out-of-fold on pad_train + pad_val (best vs params.yaml) |
|---|---|---|---|---|
| 1 (`outputs/tuning/`) | efficientnet_b3_pad, fine-tuned on pad_train (leaky) | 0.867 ± 0.020 | 0.857 ± 0.018 | 0.772 vs 0.774 |
| 2 (`outputs/tuning_b3/`) | **efficientnet_b3, the final backbone** | 0.776 ± 0.032 (lr 5.3e-4, wd 8e-5, dropout 0.28, urgent weight 4.4, hidden 128) | 0.746 ± 0.040 | 0.775 vs 0.774 |

- The leaky features inflated search 1 by about 0.09 AUC.
- On the final backbone, the tuned head is 0.03 better in pad_train CV but tied out-of-fold. The `params.yaml`
  settings are kept, and the tuned version stays a candidate (`fusion_oof_tuned`).

## 7. Sensitivity analysis (PDF §5)

### 7.1 Hyperparameters

**Learning rate, one at a time** (`tune.py --lr-sweep`, other settings fixed;
[plot](figures/tuning/tuning_b3_lr_sweep.png)). CV urgent AUC rises steadily and then flattens:

| lr | 1e-5 | 2e-5 | 4.6e-5 | 1e-4 (used) | 2.2e-4 | 4.6e-4 | 1e-3 |
|---|---|---|---|---|---|---|---|
| CV AUC | 0.595 | 0.659 | 0.718 | 0.746 | 0.762 | 0.763 | 0.762 |

Across the Hyperopt trials ([plot](figures/tuning/tuning_b3_sensitivity.png)):
- lr has Spearman +0.89 with CV AUC.
- dropout (−0.32), hidden_dim (+0.15), weight decay (+0.12) and urgent class weight (−0.06) have small, noisy
  effects.

The trials are TPE samples, not independent draws, so the one-at-a-time sweep is the cleaner read. It also suggests
lr 2e-4 to 5e-4 would add about 0.015 CV AUC. That gain did not survive the out-of-fold comparison in section 6.

### 7.2 Features (SHAP)

`src/training/explain.py` runs SHAP GradientExplainer on `P(urgent)` of the selected head:
- 200 pad_train photos as background; the 345 pad_val photos explained.
- The model was trained on these photos, so this explains its behaviour, not how well it generalises.

Mean |SHAP|:

| Input | Mean \|SHAP\| |
|---|---|
| image (all features summed) | 0.084 |
| q_changed | 0.027 |
| q_grew | 0.027 |
| q_bleed | 0.022 |
| q_changed_missing | 0.020 |
| q_grew_missing | 0.015 |
| others | < 0.01 |

- "Changed" and "grew" = yes raise P(urgent).
- "Bleed" = yes lowers it. That is worth a clinical check, since bleeding is common in BCC, which is labelled
  priority.
- Plots: [figures/sensitivity](figures/README.md).

### 7.3 Missing answers

Zeroing the missing flags drops out-of-fold AUC:
- fusion: 0.774 → 0.710
- answers only: 0.750 → 0.655

So part of the answer signal comes from how PAD-UFES-20 was collected.

| fusion_oof_rw, out-of-fold | Photos | Urgent | AUC | Recall | Flagged |
|---|---|---|---|---|---|
| every answer given | 1,608 | 137 | 0.771 | **0.796** | 44% |
| some answer missing | 338 | 72 | 0.643 | 0.958 | 87% |

Source: `outputs/analysis/missing_flags.json`.

### 7.4 Robustness and threshold (course Session 12)

`src/training/analysis.py` degrades each pad_test photo, runs it through the serving preprocessing (crop +
colour constancy) and scores it at the fixed tau:

| Condition | Urgent AUC | Recall | Flagged |
|---|---|---|---|
| no degradation (serving path) | 0.684 | 0.714 | 48% |
| blur (radius 3) | 0.619 | 0.771 | 57% |
| dark (×0.55) | 0.669 | 0.686 | 46% |
| bright (×1.5) | 0.688 | 0.829 | 60% |
| JPEG quality 15 | 0.648 | 0.857 | 76% |
| 4× lower resolution | 0.677 | 0.800 | 54% |

- Here the clean photos pass through the preprocessing a second time (they were processed by the data pipeline
  already). That is why the first row is a little below the evaluation (0.694 / 0.743).
- Blur hurts ranking the most. Heavy compression makes the model flag three photos in four.
- The intake app should check photo quality.

## 8. Registry (PDF §2.6, §8.7)

The registry code is `src/training/registry.py` plus `src/serving/triage_model.py`.

**What gets registered.** An MLflow pyfunc (models-from-code) covering the whole triage step:
- In: a raw photo path and the answers.
- Then the same preprocessing as the data pipeline: EXIF rotation, centre square crop to 384 px, Shades-of-Gray
  colour constancy, JPEG quality 92 (`src/data/preprocess.py`; a test checks it against the data pipeline's code
  and settings).
- Out: calibrated probabilities, the urgent flag and the class.
- It bundles the backbone, the fusion head (with calibration and tau) and `params.yaml`.

**Course pattern.** `register_model` → `transition_model_version_stage("Production")`, plus the MLflow 3 alias
`production`.

**Gate** (`params.yaml` `registry:`), on validation / out-of-fold metrics only:
- validation urgent AUC ≥ 0.75
- validation calibration error ≤ 0.05
- validation AUC no more than 0.01 below the current Production version
- Test recall, test calibration and the bias result are stored as warnings on the version.

**Rollback.**
- The previous Production version keeps the alias `previous`, and `registry rollback` swaps back.
- In GCS, `registry rollback-gcs` points `latest.json` at an earlier version. The image is rolled back by
  re-tagging it.

**Current state.**
- v3 = fusion_oof_rw = Production: validation AUC 0.769 vs v2's 0.774, inside the 0.01 tolerance.
- v2 = previous; v1 = archived. v1 and v2 are both fusion_oof.

**GCP push.**
- `registry push` copies Production to `gs://skinsort-data-asdr/models/skinsort-triage/v<N>/` with
  `model_info.json`, then writes `latest.json` (the deployed version) and `version.txt` (the highest number pushed,
  as in course Github_Labs/Lab4).
- GCS numbering is its own, so CI runners with a fresh MLflow registry never collide.
- CI pushes the serving image to Artifact Registry with the same number.
- **Status:** written and tested against fake buckets; not uploaded yet (team decision).

## 9. CI/CD (PDF §7)

The workflow is `.github/workflows/model-pipeline-ci.yml`, modelled on the course `ci_cd_pipeline.yml`:

| Step | PDF | How |
|---|---|---|
| Lint + unit tests on every push / PR | 7.1 | `flake8 src tests`, `pytest tests` (synthetic data; also pass inside the Docker image) |
| Training on push to main (or a new `Data-Pipeline/dvc.lock`) | 7.1 | GCP auth → `dvc pull` → backbone from GCS → `python -m src.training.pipeline` (reweighted fusion head + out-of-fold tau). Backbones need a GPU and are trained on the GCP VM |
| Automated validation | 7.2 | registry gate in the pipeline (validation AUC floor, calibration, no regression) |
| Automated bias detection | 7.3 | `bias.py` + mitigation in the pipeline; a failing slice sends an alert email |

## 10. Docker (PDF §8.1)

`docker/Dockerfile` is multi-stage, following course Docker_Labs/Lab2:
- `trainer` runs `src.training.pipeline`.
- `serving_base` runs the FastAPI app `src/serving/app.py` (`GET /health`; `POST /triage` with a photo and
  optional answers) on a mounted model.
- `serving` adds the exported Production model, which makes it the image for Artifact Registry.

`docker/docker-compose.yml` starts `serving_base` after the trainer finishes and mounts the model the trainer
exported. The repository is mounted at the same absolute path, because `mlflow.db` stores absolute artifact paths.
Both images build locally.

## 11. How to run

See the "Model pipeline" table in the [README](../README.md). The short version:

```bash
python -m src.training.train                     # GPU VM: image backbones
python -m src.training.pipeline                  # reweighted fusion + tau -> bias + mitigation -> selection -> registry -> export -> figures

```
